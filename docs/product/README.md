# 产品文档

本目录是产品叙事和对外事实边界的集中入口。它服务于产品介绍、销售演示和客户
沟通，不替代部署、开发、测试或内部 Agent 约束。所有能力表述必须能回到源码、
可执行配置或测试；设计提案不能直接变成产品承诺。

## 阅读入口

- [能力矩阵](./capability-matrix.md)：当前能力、证据来源、限制和推荐表述；
- [平台架构](./architecture.md)：组件职责、主数据边界和运行依赖；
- [跨领域合成案例](./synthetic-cases.md)：用多个领域演示同一套通用建模和治理能力，全部为构造内容。

## 产品叙事原则

1. 先说明数据、对象、关系、规则、证据和动作如何连起来，再描述助手或自动化。
2. 明确 OpenOntology 是通用本体平台，不绑定 GRC/IRM 或任何单一行业；行业案例只能作为可替换的建模示例。
3. 把“仓库已经实现”“需要外部依赖”“需要发布验收”“内部提案”分开写。
4. 所有数字、结果、客户名称和集成名称都必须标记来源；没有真实来源时使用“合成示例”。
5. 不在产品文档中放个人路径、个人账号、私有端点、内部 worktree、临时分支或生产密钥。
6. 价格、许可证、SLA、合规证明、数据驻留和客户案例需要商业负责人确认后才能发布。

## 文档状态

产品文档描述当前仓库的能力边界，不代表某一个部署环境已经通过生产验收。发布
前应将目标版本、配置、数据库迁移、真实依赖健康检查、浏览器/对象存储/外部服务
验收和回滚证据绑定到发行记录。
