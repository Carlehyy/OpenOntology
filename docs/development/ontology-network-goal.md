## 2. 架构决策【已确认】

1. SQL 本体定义 + release 快照是权威；Neo4j 只是可重建的结构投影，
   禁止把"所有查询必须走 Neo4j"绝对化到反转 SQL 权威。
2. 版本冻结模型映射、不冻结外部源数据：源 100→110 行，新查询直接
   见 110，无需重新发布。
3. 跨本体同名桥接仅展示，不自动建立业务关联；join 必须有已发布关系
   或经治理确认的业务键证据（`ontology_register_join_assertion`
   协议即证据入口）。
4. Agent 只经本体授权语义入口取数；上层不暴露裸 SQL、连接串与凭据。
5. SPL 与 typed plan 复用 `data_channel/query` 现内核，不重写引擎。
   首轮固化 text/typed 能力差异契约【待复核】：语法范围、NULL、
   类型、聚合、join 逐项写清；不把单级文本语法说成多级完整能力；
   不强制兼容厂商私有方言；不只做 UI 语法入口——多级能力必须在
   内核真实可用。
6. 结构投影承载：本体/发布版本、对象类型与属性、关系、动作/函数
   引用与可执行定义关联、mapping 资产引用、已治理跨本体关联；不含
   凭据与业务数据行，未映射数据集不入图，现有合法实例图不删。访问
   走实时授权，静态图不作授权依据。重建/回滚不串 release 快照，
   失败可见、不宣称成功。重建入口与一致性校验【待复核】。

## 3. 三类数据资产与跨层权限【已确认】

| 资产 | 持有 | 编辑语义 | 动作写回语义 |
|---|---|---|---|
| curated | 平台持有 | 平台审核 | 只提交变更，待审核，不得冒充已生效 |
| manual（人工） | 平台持有 | 编辑产生新 version | 动作产生新数据版本（按现生命周期，无需新审批） |
| integrated | 外部 MySQL/PG | 活读，不默认 snapshot | 按授权能力 select/insert/update/delete |

- 跨层访问逐叶子节点做源检查：每个叶子字段可回溯到源资产的持有
  类型、版本与授权状态；profile/release/auth/pagination 四项在叶子
  源 recheck，不允许上层一次性放行。
- 下推原则：单源过滤/分页尽量下推源端；跨源关联或聚合后的
  filter/sort/page 允许在有预算下必要计算，禁止把分页 LIMIT 盲目
  推到聚合前造成错结果。明细分页不预收全部结果；复杂聚合允许源侧
  必要扫描但受时间预算，不承诺代价只与 pageSize 成比例。分页源
  快照/keyset 语义如实标注，不承诺活源翻页冻结原数据；新查询读源
  当前值，多源非原子须披露。
- 现有 memory 链路"全量取回后在应用层分页"是已确认缺口【已确认】，
  具体代码路径与影响面【待复核】。修复方向是惰性/源端 keyset 分页：
  授权重验之后允许受限续查（bounded continuation），不要求全表重算，
  也不固化"只能持有内存旧 handle、不可重开源查询"的旧实现；跨用户
  或越权游标必须沿用现有可验证的 403/404/410 契约拒绝，不得新增
  语义不明的 HTTP 行为。

## 4. 查询预算【已确认】

预算是多维资源契约，不只 pageSize：管道复杂度（命令数/源数）、输入
传输量、中间结果体积、输出行数与字节、时间、并发、内存。超预算必须
超限显式拒绝并说明层级与维度，不得静默截断或重置预算。预算分两层：
各执行层独立预算 + 整条逻辑查询总预算，必须测"各层未超但累计超
总限"。部分读取后拒绝只能报"未完成/无完整结果 + 资源已释放"，
不得报"未执行"，不得把已读片段当完整结果。"资源释放"须可观察：
源端 scope/cursor 关闭、query ticket/handle 注销、内存 reservation
归还、自有临时资源回收，不得以 toast 代替。验收用小 fixture 低阈值
触发。明细分页测试用确定性 N=500、page=20：仅必要列、源端过滤分页、
总传输受限（单页 20 行 + 下一页探测 1 行 + 明示检查开销）；复杂
跨源聚合允许源侧必要扫描，平台侧结果/中间受预算，不强制单页 ≤21
行。落地时优先复用
`memory_budget.py`/`limits.py` 既有机制【待复核其覆盖维度】，新增
维度并入现有配置体系，不建平行配置。

## 6. 受控动作【已确认】

1. 复用超级助手五工具与确认/幂等/审计链路（prepare → 确认 →
   execute → 审计），不另起炉灶。确认前 manual version、curated
   待审记录、integrated 源三处零业务写；execute 审计记录动作、
   目标源、变更行数、操作者、时间、幂等键，且不可被动作删除。
2. 写回必须按映射命中真实来源；禁止改写本地孤儿副本后报成功
   （假成功是最高优先级缺陷）。执行结果为未知、部分成功或失败时，
   一律不得向用户呈现为完整成功。
3. 权限口径按现有 RBAC + profile + 实际源权限逐动作验证；不做
   "viewer 必然没有 prepare"之类一刀切假设，也不因角色显示按钮
   就默认后端放行。
4. 定位与并发：写操作以完整稳定主键定位行 + expected token 并发
   校验；单行 insert/update/delete 按授权与字段来源执行；不可逆
   派生属性、聚合属性、定位多义行拒绝写；read-only 可读禁不安全
   写、不造本地副本；幂等重放遇 unknown 不自动重放，人工裁决。
5. 生效语义：curated 走"待审→批准→查询可见"，批准前零生效；被拒
   或源出新版本后旧批准失效（须有断言）。manual 新版本内容与查询
   可见一致。integrated 以真实源最终值+新查询核对；无稳定 PK 可读
   但禁不安全写。
6. 生产总闸只对本轮专用测试环境按现权限配置，不得误开他人服务。
7. 跨 DB 多步动作原子性暂缓：首版执行前显式拒绝未支持组合并给明确
   错误，拒绝时源侧零变更；现有合法单源动作不得一刀切禁用，且须
   正例回归。
8. 源账号操作级权限的自动探测只作建议展示，不作为强依赖：平台配置
   与源端权限共同约束，源端收回权限后执行仍必须被拒绝。
